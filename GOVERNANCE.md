# Governance

Duskly is maintainer-led with lazy consensus.

## Maintainers

Maintainers are listed in `.github/CODEOWNERS`. They review PRs, triage issues, cut releases, and make final calls when consensus is unclear.

## Decision Making

Most changes are accepted through pull request review. Small changes can merge after one maintainer approval and passing CI. Larger product, security, licensing, or architecture changes should be discussed in an issue before implementation.

## Contributions

All commits must include a DCO `Signed-off-by` line. CI enforces this on pull requests.

## Project Direction

The public roadmap is intentionally lightweight. Maintainers may decline features that increase hosted-service risk, weaken privacy/security, or add maintenance burden without a clear user benefit.
